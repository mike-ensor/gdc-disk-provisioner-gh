# Clean Installation Paths Pre-Turnup Validation Redesign

**Date:** 2026-10-05  
**Author:** AI Product Manager / Systems Architecture Specialist  
**Target Repositories:** `gdc-companion` (`crates/collector`) & `gdc-disk-provisioner`  
**Reference Report:** `https://gdc-companion.ensor-labs.com/?download=true&report_id=1ef84ed3-8d02-4b93-b98f-1515ad9755b5` (Node `192.168.9.246`)  

---

## 1. Context & Problem Statement

In the Google Distributed Cloud (GDC) bare-metal provisioning lifecycle, diagnostic collector reports generated by `gdc-collector` evaluate `gdc_os_prerequisites`. Prior to cluster inception (`STAGE 6: CLUSTER_TURNUP`), `gdc-collector` executes a preflight check named `clean_installation_paths`.

### Existing Implementation & Deficiencies
Previously, `clean_installation_paths` checked for the emptiness of two directories:
1. `/var/lib/etcd` (`etcd_empty_check`)
2. `/etc/kubernetes` (`kubernetes_empty_check`)

This check suffered from critical architectural flaws:
- **Non-Exclusivity of `/var/lib/etcd`**: In GDC's storage architecture, `/var/lib/etcd` is a dedicated logical volume formatted with `mkfs.ext4`. Standard filesystem initialization generates `lost+found`. Furthermore, permissions adjustments (`chown 2003:2003`) or non-Kubernetes filesystem operations trip the check.
- **False Failures on Idempotent Re-Runs**: On nodes where provisioning was scheduled to stop at `CLUSTER_READY` (`stop_stage: CLUSTER_READY`), but where a cluster had already been created (or on stage re-runs), `gdc-collector` marked `CLUSTER_TURNUP` as `BYPASSED`. Because the stage was `BYPASSED`, `gdc-collector` evaluated `clean_installation_paths` rather than `populated_control_plane`, erroneously reporting `FAIL` on an otherwise healthy, operational cluster.

## 2. Requirements & Goals

### 2.1 Functional Requirements
- **FR-1 (Cluster Name Resolution):** Dynamically extract `cluster_name` from `/etc/ansible/facts.d/gdc.fact` (`cluster.cluster_name`) or `/etc/gdc/fallback-config.json`, falling back to subdirectory discovery under `/var/gdc-install/bmctl-workspace/`.
- **FR-2 (Eliminate `/var/lib/etcd` Check):** Remove `/var/lib/etcd` from the clean path assertion, as it is a raw filesystem mount rather than a definitive Kubernetes cluster marker.
- **FR-3 (Target GDC-Specific Artifacts):** Validate the cleanliness of:
  - `/var/gdc-install/bmctl-workspace/<cluster_name>`
  - `/etc/kubernetes/admin.conf`
- **FR-4 (Pristine State Detection):** On fresh bare-metal nodes, assert that `/var/gdc-install/bmctl-workspace/<cluster_name>` is absent (or empty of cluster configs) and `/etc/kubernetes/admin.conf` is absent, reporting **`PASS`**.
- **FR-5 (Idempotent Operational State Awareness):** If `/etc/kubernetes/admin.conf` and `<cluster_name>-kubeconfig` exist, run a non-blocking health probe:
  ```bash
  kubectl --kubeconfig=/etc/kubernetes/admin.conf get nodes --request-timeout=3s
  ```
  If the command succeeds, report **`PASS`** with status `"Cluster already initialized and operational (idempotent re-run)"`.
- **FR-6 (Dirty State Detection):** If cluster files exist but the cluster is non-operational, report **`FAIL`** with clear remediation hints instructing the operator to run cluster cleanup.
- **FR-7 (Preserve Post-Turnup Checks):** When executed during or after `CLUSTER_TURNUP`, continue to assert `populated_control_plane` using the presence of `/etc/kubernetes/admin.conf`.

## 3. Detailed Architecture

### 3.1 GDC Collector (`crates/collector/src/prereqs.rs`)

Replace the raw `read_dir("/var/lib/etcd")` and `read_dir("/etc/kubernetes")` with:

```rust
pub fn check_clean_installation_paths(
    cluster_name: &str,
    is_cluster_turnup_or_later: bool,
) -> serde_json::Value {
    let workspace_cluster_dir = format!("/var/gdc-install/bmctl-workspace/{}", cluster_name);
    let admin_conf = std::path::Path::new("/etc/kubernetes/admin.conf");
    let cluster_kubeconfig = format!("{}/{}-kubeconfig", workspace_cluster_dir, cluster_name);

    let workspace_has_config = std::path::Path::new(&cluster_kubeconfig).exists()
        || (std::path::Path::new(&workspace_cluster_dir).is_dir()
            && std::fs::read_dir(&workspace_cluster_dir)
                .map(|mut entries| entries.any(|e| {
                    if let Ok(entry) = e {
                        let name = entry.file_name().to_string_lossy().to_string();
                        name.ends_with(".yaml") || name.ends_with("-kubeconfig")
                    } else {
                        false
                    }
                }))
                .unwrap_or(false));

    let admin_conf_exists = admin_conf.exists();

    // Check if an existing cluster is already operational (idempotent re-run)
    let cluster_already_healthy = admin_conf_exists
        && run_bash("kubectl --kubeconfig=/etc/kubernetes/admin.conf get nodes --request-timeout=3s").is_ok();

    if is_cluster_turnup_or_later || cluster_already_healthy {
        let (status, msg) = if cluster_already_healthy {
            ("PASS", "Cluster already initialized and operational (idempotent re-run)")
        } else if admin_conf_exists {
            ("PASS", "/etc/kubernetes/admin.conf is populated with active cluster credentials")
        } else {
            ("FAIL", "/etc/kubernetes/admin.conf missing after turnup")
        };

        serde_json::json!({
            "details": "Control plane state and credentials check",
            "remediation": "Inspect /var/gdc-install/logs/create_cluster.log and bmctl-workspace logs.",
            "status": status,
            "test_results": [
                {
                    "test_name": "control_plane_operational_check",
                    "status": status,
                    "output": msg
                }
            ]
        })
    } else {
        let is_clean = !workspace_has_config && !admin_conf_exists;
        serde_json::json!({
            "details": "Pristine cluster workspace and credentials check",
            "remediation": "Clean /var/gdc-install/bmctl-workspace/<cluster-name> and remove /etc/kubernetes/admin.conf before installation.",
            "status": if is_clean { "PASS" } else { "FAIL" },
            "test_results": [
                {
                    "test_name": "workspace_clean_check",
                    "status": if !workspace_has_config { "PASS" } else { "FAIL" },
                    "output": if !workspace_has_config {
                        "Cluster workspace is clean or uninitialized"
                    } else {
                        "Residual cluster configuration files found in workspace"
                    }
                },
                {
                    "test_name": "admin_conf_clean_check",
                    "status": if !admin_conf_exists { "PASS" } else { "FAIL" },
                    "output": if !admin_conf_exists {
                        "/etc/kubernetes/admin.conf is absent (clean)"
                    } else {
                        "Pre-existing /etc/kubernetes/admin.conf detected without operational cluster"
                    }
                }
            ]
        })
    }
}
```

## 4. Verification & Testing Strategy

1. **Unit Testing (`crates/collector/src/prereqs.rs`)**:
   - `test_clean_installation_paths_pristine`: Mocks absent workspace and absent `admin.conf` $\rightarrow$ verifies `status == "PASS"`.
   - `test_clean_installation_paths_idempotent_operational`: Mocks present `admin.conf` with simulated successful `kubectl get nodes` $\rightarrow$ verifies `status == "PASS"`.
   - `test_clean_installation_paths_dirty`: Mocks present configuration files with failed `kubectl` probe $\rightarrow$ verifies `status == "FAIL"`.
2. **Integration Verification**:
   - Run collector locally in `gdc-companion` and compile binary with `cargo test -p gdc-collector`.
